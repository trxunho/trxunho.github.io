内容管理后台

使用你的 GitHub 个人访问令牌（PAT，需 repo 权限）登录，即可在浏览器中直接编辑网页文字、图片与视频，并在各栏目下新增文章。所有更改会提交到仓库 trxunho/robotics-portfolio-public 并自动重新部署。

不会生成令牌？点这里看详细步骤（两种方式任选其一）

方式一 · 经典令牌（最简单，推荐）

  1. GitHub 头像 → Settings → Developer settings → Personal access tokens → Tokens (classic)
  2. Generate new token (classic)
  3. 勾选 repo（公开仓库勾 public_repo 也够）→ 生成 → 复制

方式二 · 精细化令牌（Fine-grained）
注意：「Read and write」不在勾选列表里，它是选完权限之后才出现的下拉项。

  1. Tokens (fine-grained) → Generate new token
  2. Repository access 选 Only select repositories → 选中 trxunho/robotics-portfolio-public
  3. Permissions 里点 + Add permissions，在搜索框输入 Contents，勾上 Contents，点面板底部的 Add permissions 按钮
  4. 回到 Permissions 表格，找到刚加进来的 Contents 行，把右侧下拉从 No access 改成 Read and write
  5. Generate token → 复制（令牌只显示一次）

两种方式都只需「该仓库」的读写权限；Metadata 是自动带的只读项，不用管。

令牌仅保存在当前浏览器会话（关闭标签页即清除），并直接用于访问 GitHub API，不会发送给任何第三方。

保存后多久能在线上看到？两个站点的更新机制

① trxunho.github.io（GitHub Pages）：保存后由 GitHub Actions 自动构建并部署，通常 1–2 分钟 即可上线，无需等待定时任务。

② tanrongxin-cms.app.workbuddy.host（WorkBuddy）：由部署同步任务更新。如需立即生效，可在 WorkBuddy 的「自动化」面板找到「同步作品集站点」任务，点击 运行 手动触发（也默认每小时自动同步一次）。

注：GitHub Pages 自动部署需要在仓库 robotics-portfolio-public 的 Settings → Secrets 中配置一个名为 PAGES_DEPLOY_TOKEN 的令牌（即你登录后台所用的同一枚 repo 令牌即可）。
